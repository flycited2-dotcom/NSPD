# Земельная разведка по Трудовому

Локальное приложение для поиска пространственных кандидатов, ведения проверок и подготовки рабочего досье. Создано по `TZ_Zemelnaya_razvedka_NSPD_Trudovoe_v1.0.docx`.

**Текущий результат (29.09.2026):** добавлен [живой поиск НСПД](http://127.0.0.1:8765/nspd.html). Подтверждены поиск по кадастровому номеру без переноса сессии и получение пяти реальных участков через Chrome. Есть карта, экспорт GeoJSON и отдельный список «В разработке». Прямой пространственный POST пока нестабилен; доступен датированный снимок ответа браузера. Полнота покрытия не подтверждена. GIS-анализ загруженных полных слоёв сохранён. Официальная граница Трудового, полный кадастр и юридически проверенные кандидаты пока не получены; полный пилот ТЗ не завершён. Подробности: [диагностика](NSPD_DIAGNOSTICS_2026-09-29.md).

## Запуск

1. Дважды нажмите **START.cmd** в этой папке.
2. Откроется [локальное приложение](http://127.0.0.1:8765/).
3. Кнопка «Посмотреть учебный пример» показывает работу на искусственных данных в отдельном проекте. Переключатель слева возвращает в реальный проект Трудового.

Python и зависимости уже подготовлены в `.venv`. На другом компьютере нужен Python 3.11+; при первом запуске загрузятся пакеты из `requirements.txt`. Приложение слушает только `127.0.0.1`, работает, пока компьютер включён, и не добавляет себя в автозагрузку. Для остановки используйте **STOP.cmd**. Запуск из терминала:

```powershell
.\.venv\Scripts\python.exe app.py
```

## Реальный поиск

В разделе «Данные и слои» сначала загрузите **официальный полигон области** в GeoJSON, затем **полную кадастровую геометрию**. Для каждого слоя укажите источник, дату, исходный CRS и основание считать источник официальным. Для кадастра нужно подтвердить полноту и покрытие всей области. Если данные частичные, уменьшите область до подтверждённого покрытия или получите недостающие страницы.

Программа принимает GeoJSON FeatureCollection с Polygon/MultiPolygon. Порядок координат — X/Y; в EPSG:4326 это долгота/широта. Для другой системы координат укажите распознаваемый EPSG или точное определение CRS. Высота отбрасывается. Неизвестную МСК нельзя объявлять EPSG:4326. WMS, скриншоты, PDF и линии дорог не подменяют полигональные данные: линии предварительно преобразуются в обоснованные полосы в GIS, например QGIS.

Роли слоёв:

| Слой | Использование |
|---|---|
| Граница исследования | Ограничивает область; приблизительный центр карты не участвует в расчёте |
| Учтённые участки | Вычитаются из области |
| Дороги и территории общего пользования | Вычитаются; расстояние до них не подтверждает законность подъезда |
| Подтверждённые исключения | Вычитаются только после установления запрета для выбранной цели |
| Застройка | Вычитается геометрия загруженных объектов |
| ЗОУИТ и ограничения | Пересечения фиксируются для правового анализа; все зоны подряд не исключаются |
| ПЗЗ | Атрибуты пересекающихся зон включаются в досье |
| Кадастровые кварталы | Атрибуты пересекающихся кварталов включаются в досье |

Вместо файла можно указать публичную HTTPS-ссылку на **полный GeoJSON**. Ссылки с токенами, авторизация, редиректы, приватные адреса и ответы больше 25 МБ не поддерживаются. Известные признаки неполной пагинации приводят к отказу импорта. Неизвестную пагинацию программа не угадывает: полноту должен подтвердить источник. Автоматического обхода всех страниц НСПД или универсального WFS-коннектора в этой версии нет.

После импорта нажмите «Запустить поиск». Алгоритм:

1. Проверяет геометрию, CRS и покрытие кадастрового слоя.
2. Переводит данные в локальную равновеликую проекцию LAEA в метрах.
3. Вычитает учтённые участки, дороги, застройку и подтверждённые исключения.
4. Отбрасывает слишком маленькие окна и контуры, в которых не помещается окружность заданного диаметра. Этот фильтр не гарантирует отсутствие всех узких перешейков.
5. Сохраняет крупные окна с отметкой о необходимости проектирования меньшего контура. Верхняя площадь не режет территорию автоматически.
6. Находит пересечения с ограничениями, ПЗЗ, кварталами и соседние участки.
7. Сохраняет кандидатов и историю. Повторный расчёт одинаковых контуров сохраняет ID и заметки; изменение исходных данных сбрасывает подтверждения, прежние доказательства остаются в истории.

Участки с другим контуром получают новый ID; старые сохраняются вне последнего расчёта. Геометрически похожие, но не одинаковые контуры автоматически не объединяются. Проверяйте историю перед повторной разработкой места. Округления и смена проекции не заменяют кадастровые измерения и координаты в надлежащей МСК.

## Досье и процедура

В карточке доступны стадия «В разработке», заметки, дата следующей проверки, номер/источник решения и 17 проверок. Вывод «Подтверждено» означает выполненную проверку без выявленного препятствия. Он требует источника, даты и обоснования. Это внесённые человеком доказательства, а не автоматическая юридическая экспертиза.

Зелёный статус появляется только после основных проверок. Для стадии «ПОДАЧА» дополнительно нужны подтверждения СРЗУ/основания её неприменимости, готового заявления с приложениями и проверенного канала подачи. Проверки старше 30 дней требуют актуализации по правилу приложения; это не законный срок действия документов. Изменение слоёв делает прежний расчёт неактуальным.

В этой версии **не формируются юридически готовые СРЗУ и заявления**, не выполняются вход в Госуслуги, подпись, отправка, регистрация права или участие в торгах. Готовность отмечается после фактической подготовки документов вне приложения. Автоматических уведомлений и фонового мониторинга извещений нет; дата следующей проверки хранится в досье и экспорте.

Муниципальный [регламент № 813 от 05.06.2026](https://trudovskoe-rk.ru/wp-content/uploads/2026/06/813.pdf) описывает предоставление муниципальной земли без торгов и называет администрацию Трудовского сельского поселения. Нельзя переносить это полномочие на любую публичную землю без проверки принадлежности и компетенции. Для аренды на торгах опубликован [регламент № 776](https://trudovskoe-rk.ru/wp-content/uploads/2026/06/776.pdf), для СРЗУ — [регламент № 187](https://trudovskoe-rk.ru/wp-content/uploads/2026/02/187_12.02.2026-2.pdf).

Применимость [статьи 39.18 ЗК РФ](https://www.consultant.ru/document/cons_doc_LAW_33773/3e878d61b0de409120ad70762779b6616b55d7d9/) проверяется отдельно для заявителя, цели и территории. Наличие окна не даёт основания немедленно регистрировать право. Актуальная редакция нормы и местного регламента проверяется перед подачей. Ссылки в приложении — исходные ориентиры; полный правовой анализ конкретной территории ещё не выполнен.

## Экспорт и хранение

«Выгрузить досье» скачивает ZIP:

- `candidates.geojson` и `registry.csv`;
- печатные HTML-досье и полный `dossiers.json` с историей;
- координаты вершин WGS84 и геометрия в расчётной LAEA с WKT определения CRS;
- источники, журнал и `NSPD_ENDPOINT_REGISTRY` в JSON/CSV;
- следующие действия до подачи.

HTML-досье можно открыть и распечатать в PDF из браузера. Оно не является СРЗУ или официальным заявлением. GeoJSON включает историю кандидатов: поле `active` отличает текущие результаты от прежних.

База — `data/land.sqlite`. Исходные версии слоёв сохраняются по SHA-256 в `data/layer_snapshots`, удалённые GeoJSON — в `data/evidence`. Для резервной копии остановите приложение и скопируйте всю папку `data`. Первоначальный Word-файл не изменён. Журналы запуска находятся в `data/server*.log`.

## НСПД и продолжение технического аудита

В разделе «Источники и НСПД» есть проверка доступности и локальный импорт HAR. Из HAR извлекаются URL-шаблоны, методы, имена параметров, код ответа и схема верхнего уровня JSON. Заголовки авторизации, cookies, тела запросов и значения query-параметров не сохраняются; исходный HAR не записывается. Длинные идентификаторы в пути заменяются шаблоном. Не загружайте HAR других сайтов.

Наблюдение запроса не подтверждает его публичность, допустимость массового использования, CRS или полноту. Перед подключением необходимо в рабочем браузере получить каталог актуальных слоёв, воспроизвести поиск/клик, проверить CRS, пагинацию, ограничения, условия использования и возможность законного получения полной геометрии. Старые ID слоёв и непроверенные URL не встроены.

Технические библиотеки: [Shapely](https://shapely.readthedocs.io/en/stable/manual.html), [pyproj](https://pyproj4.github.io/pyproj/stable/api/transformer.html), [Leaflet](https://leafletjs.com/reference.html). Leaflet поставляется локально; интернет нужен только для внешних источников и необязательной подложки OpenStreetMap.

## Командный режим и тесты

```powershell
.\.venv\Scripts\python.exe cli.py --project trudovoe import input-layer.json
.\.venv\Scripts\python.exe cli.py --project trudovoe search --min-area 400 --max-area 2500 --min-width 12
.\.venv\Scripts\python.exe cli.py --project trudovoe export result.zip
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
```

CLI-импорт принимает объект `{ "role": "boundary", "metadata": { "title": "…", "source": "…", "checked_at": "YYYY-MM-DD", "crs": "EPSG:4326", "official": true }, "geojson": { "type": "FeatureCollection", "features": [] } }` с фактической геометрией. Для кадастра в metadata нужны `complete: true` и `coverage` — геометрия полного покрытия в исходном CRS.

Проверены пространственное вычитание и геодезическая площадь, неполные/ошибочные данные, ограничения статусов, история, повторные расчёты, конкурентное обновление исходных слоёв, разделение проектов, очистка HAR, экспорт и HTTP-сценарии. На момент сдачи — 28 проходящих тестов.
